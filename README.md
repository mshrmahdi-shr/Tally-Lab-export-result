# Tally — native AutoCAD DXF export

Read lab certificates in Tally as usual. Each results report and borehole has a
**Download AutoCAD DXF** button. It downloads the currently displayed analyses,
borehole names, sampling rounds and depths using the existing report data.
Soil and groundwater exports have separate keys and filenames, including when
both use the same standards table. The optional MAGIC CSV importer remains available.

The downloaded DXF contains native `ACAD_TABLE` entities, merged cells, table styles
and graphical caches. Open the DXF directly in AutoCAD; no LISP is generated.
Text and grids in anonymous blocks are the table display cache, not a replacement
for the native table. There is no CAD conversion service or ODA runtime dependency.

## Run and test

Serve this folder over HTTP, for example `python -m http.server 8080`.

- `npm ci` then `npm test` (Node.js 24 or later)
- Optional independent reader audit: install `ezdxf==1.4.4` and run
  `python scripts/audit-dxf.py path/to/export.dxf`.

`native-dxf-base.js` is an empty R2004 document skeleton generated by
`scripts/build-dxf-base.py` using ezdxf (MIT). Regeneration needs Python and ezdxf;
exporting in the browser needs neither. `magic-native-table.js` writes the native
entities and graphics. User text is escaped for MTEXT and non-ASCII characters use
DXF Unicode escapes. The document has unspecified drawing units and uses Arial.

The export has been audited with an independent DXF reader and round-tripped
through DXF → DWG → DXF without losing the tested table cells. Direct editing in
AutoCAD still needs acceptance testing, especially fonts and unusually long text.
This change adds the export workflow; account login, cloud project storage,
subscriptions and server-enforced usage limits are not implemented here.
